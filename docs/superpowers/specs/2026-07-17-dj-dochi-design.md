# DJ DOCHI UX 프로토타입 설계

## 1. 목표와 범위

DJ DOCHI는 사용자의 플레이리스트 캡처 또는 음악 목록을 받아 취향을 분석해 주는 AI DJ 고슴도치 서비스다. 이번 단계에서는 GPT API, OCR, 서버 저장을 연결하지 않고 브라우저 안에서 동작하는 UX 프로토타입만 만든다.

구현 범위는 다음과 같다.

- Idle, Greeting, Upload, Loading, Result의 전체 화면 흐름
- 업로드한 이미지의 로컬 미리보기
- 붙여넣은 음악 목록의 원문 확인과 수정
- 입력을 삭제하거나 다시 선택하는 동작
- 입력이 있을 때만 활성화되는 `도치에게 건네기` 버튼
- 더미 분석 결과와 더미 플레이리스트
- 나중에 실제 캐릭터 PNG로 교체할 수 있는 에셋 로더와 플레이스홀더

분석 결과는 고정된 더미 데이터로 출력하며, 새로고침 후 상태를 복원하거나 서버에 파일을 전송하는 기능은 범위에서 제외한다.

## 2. 사용자 흐름

```text
Idle
  ↓ 캐릭터/시작 CTA 클릭
Greeting
  ↓ 플레이리스트 보여주기
Upload (input 선택)
  ├─ 캡처 업로드 → 이미지 미리보기 확인
  └─ 목록 붙여넣기 → 음악 목록 원문 확인/수정
        ↓ 입력이 있을 때만 활성화
      도치에게 건네기
        ↓
      Loading
        ↓ 짧은 데모 타이머
      Result
        └─ 다시 믹스하기 → Idle
```

`Upload`를 별도의 상태로 유지하고 내부 모드로 `choose`, `image-review`, `text-review`를 사용한다. 이렇게 하면 요구된 상태 흐름을 유지하면서도 입력 확인 단계를 명확하게 표현할 수 있다.

### Idle

검은 배경의 중앙 무대에 눈을 감고 헤드폰을 쓴 DJ 도치를 배치한다. LP 턴테이블, 앰비언트 라이트, 작은 이퀄라이저 바를 주변 장식으로 사용한다. 중앙 캐릭터 또는 `START SESSION` CTA를 클릭하면 Greeting으로 이동한다.

### Greeting

도치의 말풍선에 다음 문구를 출력한다.

> 엇? 손님이네. 요즘 듣는 플레이리스트 좀 보여줄래?

`플레이리스트 캡처 업로드`와 `음악 목록 붙여넣기` 두 버튼을 제공한다. 두 버튼은 Upload의 입력 선택 모드를 각각 연다.

### Upload: 입력 선택

이미지 업로드는 숨겨진 `input[type=file]`을 사용하고 이미지 MIME 타입만 허용한다. 파일을 선택하면 즉시 로컬 object URL을 만들고 image-review 모드로 이동한다. 파일 내용은 분석하거나 업로드하지 않는다.

텍스트 입력은 textarea가 있는 text-review 모드로 이동한다. textarea는 사용자가 여러 줄 음악 목록을 그대로 붙여넣고 수정할 수 있게 한다.

### Upload: 입력 확인

이미지 확인 화면에는 파일명, 이미지 미리보기, `다시 선택`, `삭제`, `도치에게 건네기`를 표시한다. `다시 선택`은 파일 선택 창을 다시 열고, `삭제`는 object URL을 해제한 뒤 입력 선택 화면으로 돌아간다.

텍스트 확인 화면에는 textarea를 그대로 노출하고 입력된 줄 수를 작은 메타 정보로 보여준다. textarea는 확인 화면에서도 계속 편집 가능하므로 사용자는 별도 모드 전환 없이 내용을 수정할 수 있다. `삭제`는 텍스트를 비우고 입력 선택 화면으로 돌아간다.

두 확인 화면 모두 이미지가 존재하거나 텍스트가 공백을 제외하고 한 글자 이상일 때만 `도치에게 건네기`를 활성화한다. 버튼을 누르면 Loading으로 이동한다.

### Loading

DJ 부스가 어둡게 깜빡이고 턴테이블 링, 이퀄라이저, 로딩 점이 움직인다. 다음 문구를 표시한다.

- `잠깐만.`
- `도치가 음악을 분석하는 중...`

분석은 실제로 하지 않고 약 1.8초 뒤 Result로 전환한다. 입력 데이터는 화면 전환 확인에만 사용하고 결과 생성에는 사용하지 않는다.

### Result

안경을 쓴 도치와 종이 믹스테이프 카드를 보여준다. 말풍선 문구는 다음과 같다.

> 봤어. 취향 좋네.

더미 플레이리스트에는 트랙명, 아티스트, 분위기 태그, 별점 또는 BPM 같은 짧은 메타 정보를 포함한다. `다시 믹스하기`를 누르면 기존 object URL을 정리하고 Idle로 돌아간다.

## 3. 시각 방향

- 전체 배경: 거의 검은 `#09080b`, 깊은 보라색 그림자, 앰버와 코랄 하이라이트
- 캐릭터: 둥근 몸과 얼굴, 큰 삼각형 가시 덩어리, 커다란 헤드폰을 CSS placeholder로 표현
- 재질: 평면적인 면, 낮은 폴리곤 실루엣, 약한 플라스틱 광택
- UI: 오래된 게임 메뉴와 MP3 플레이어를 섞은 패널, 픽셀에 가까운 작은 라벨, 굵은 산세리프 숫자
- 장식: LP판, 턴테이블 암, 노브, LED 이퀄라이저, 작은 상태 배지
- 모션: 캐릭터의 미세한 좌우 바운스, LP 회전, LED 점멸, 로딩 링 회전

레퍼런스 이미지는 사이트에 포함하지 않는다. 실제 에셋이 없을 때는 캐릭터 영역의 크기와 배치를 유지하는 CSS placeholder를 표시한다.

## 4. 에셋 교체 설계

다음 경로를 상태별 캐릭터 에셋의 기준 경로로 사용한다.

```text
src/assets/dochi/dochi-idle.png
src/assets/dochi/dochi-surprised.png
src/assets/dochi/dochi-thinking.png
src/assets/dochi/dochi-result.png
```

`DochiCharacter` 컴포넌트는 `import.meta.glob`으로 해당 폴더의 PNG를 선택적으로 수집하고 현재 상태에 맞는 파일을 시도한다. 파일이 없거나 이미지 로드에 실패하면 동일한 aspect ratio와 컨테이너 크기의 `DochiPlaceholder`를 렌더링한다. 따라서 나중에 위 파일만 추가해도 화면 코드는 변경하지 않는다. 결과 화면의 안경/종이 느낌은 실제 result 에셋이 추가되기 전까지 placeholder의 액세서리로 표현한다.

## 5. 컴포넌트와 데이터 경계

- `App`: 최상위 상태, 입력 데이터, 화면 전환, Loading 타이머를 관리
- `StageShell`: 공통 무대 배경, 상단 브랜드, 상태 인디케이터, 장식 배치
- `DochiCharacter`: 상태별 이미지 시도와 placeholder fallback
- `IdleScreen`: 시작 화면
- `GreetingScreen`: 말풍선과 입력 방식 선택 버튼
- `UploadScreen`: 입력 선택, 이미지 확인, 텍스트 확인을 mode로 분기
- `LoadingScreen`: 분석 중 애니메이션과 문구
- `ResultScreen`: 결과 도치, 믹스테이프 카드, 더미 트랙 목록
- `Turntable`, `Equalizer`, `SpeechBubble`, `RetroButton`: 재사용 시각 요소

입력 데이터는 다음과 같이 단순하게 유지한다.

```ts
type Screen = 'idle' | 'greeting' | 'upload' | 'loading' | 'result';
type UploadMode = 'choose' | 'image-review' | 'text-review';

type PlaylistInput = {
  imageFile: File | null;
  imageUrl: string | null;
  pastedText: string;
};
```

이미지와 텍스트는 동시에 보관하지 않고 마지막으로 선택한 입력만 사용한다. 모드 전환이나 삭제 시 이전 object URL을 `URL.revokeObjectURL`로 해제한다.

## 6. 반응형·접근성

- 데스크톱에서는 중앙 무대를 최대 1180px로 제한하고 좌우에 장식을 배치한다.
- 모바일에서는 장식 수를 줄이고 카드와 캐릭터를 세로로 쌓는다.
- 모든 버튼은 실제 `button` 요소, 파일 input은 명시적인 label과 연결한다.
- 이미지 미리보기에는 파일명을 보조 텍스트로 표시하고 캐릭터 이미지에는 상태별 alt를 제공한다.
- 비활성 `도치에게 건네기`는 시각적으로 낮은 대비로 표시하되 초점 가능한 요소와 구분한다.
- `prefers-reduced-motion`이 켜지면 회전과 바운스 애니메이션을 줄인다.

## 7. 검증 기준

구현 후 다음을 확인한다.

1. `npm run build`가 성공한다.
2. 시작 화면 클릭으로 Greeting, 입력 방식 버튼으로 Upload에 도달한다.
3. 이미지 선택 후 실제 미리보기가 표시되고, 삭제/재선택이 동작한다.
4. 빈 텍스트에서는 `도치에게 건네기`가 비활성화되고, 내용 입력 후 활성화된다.
5. 텍스트 수정/삭제가 동작하고, 전달 버튼 클릭 전에는 Loading으로 이동하지 않는다.
6. 전달 버튼 이후 Loading을 거쳐 Result가 표시된다.
7. 캐릭터 PNG가 없을 때 placeholder가 표시되고, 해당 파일을 추가하면 fallback 없이 이미지가 사용된다.
8. 모바일 폭에서도 콘텐츠가 잘리지 않고 버튼이 눌린다.
