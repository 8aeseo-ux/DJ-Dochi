# DJ DOCHI 스케치북 UI 가독성 개선 디자인

## 목표

현재의 한 장짜리 음악 작업 노트 감성과 손그림 선은 유지하되, 모든 상태에서 제목·설명·도치 대사·입력·버튼이 장식과 캐릭터보다 먼저 읽히게 한다.

이번 변경은 화면 배치와 타이포그래피만 다룬다. OCR, AI Vision, 취향 분석, 카탈로그 검증, LP 물리, 카메라, 폴라로이드, 믹스테이프 결과의 상태와 기능은 변경하지 않는다.

## 현재 문제

- 도치, DJ 컨트롤러, 대화창, 선택 메뉴, 입력 패널이 같은 `room-stage` 안에서 절대 배치되어 화면 폭과 상태에 따라 겹칠 수 있다.
- 투명한 패널 뒤로 캐릭터와 배경 낙서가 보여 버튼과 설명의 대비가 낮다.
- 업로드 영역 안에도 장식과 반투명 표현이 남아 핵심 입력 동작이 덜 명확하다.
- Gaegu 손글씨 폰트가 대사, 버튼, 제목, 결과 목록까지 확장되어 긴 한국어 문장의 가독성이 떨어진다.
- 기존 반응형 규칙은 920px과 720px 중심이라 1024px, 768px에서 UI가 사용할 독립 공간을 보장하지 않는다.

## 선택한 접근

### A. 좌측 캐릭터 무대 + 우측 읽기 패널

데스크톱에서는 장면과 인터페이스를 서로 다른 레이아웃 영역으로 분리한다.

- 1100px 이상: 시각 영역 58%, 인터페이스 영역 42%
- 901px~1099px: 시각 영역 54%, 인터페이스 영역 46%
- 900px 이하: 시각 영역 위, 인터페이스 영역 아래
- 모바일: 시각 영역 높이를 제한하고 인터페이스는 일반 문서 흐름과 페이지 스크롤을 사용

Idle에서는 인터페이스 영역을 숨기고 시각 영역이 전체 폭을 사용한다. 대화가 시작되면 같은 작업실 안에서 2열 또는 세로 스택으로 자연스럽게 전환한다.

## 컴포넌트 경계

`DochiRoom`에 레이아웃 목적의 최소 래퍼만 추가한다.

### `room-visual`

다음 요소만 포함한다.

- 작업대, 스피커, 콘솔, 이퀄라이저
- Workshop 효과
- 도치 캐릭터
- DJ 컨트롤러
- LP 인터랙션과 회전 반응
- Idle 안내

이 영역은 `position: relative`와 `overflow: hidden`을 사용한다. 도치, 컨트롤러, LP는 이 경계를 벗어날 수 없다.

### `room-interface`

다음 읽기·입력 요소를 포함한다.

- DialogueBox
- ChoiceMenu
- PlaylistInputPanel
- 추출·취향 분석 상태 패널
- PlaylistExtractionReview
- 추출·취향 분석 오류 패널

인터페이스는 불투명한 종이색 배경을 사용한다. 장면과 낙서는 이 영역 뒤에 표시되지 않는다.
래퍼는 안정적인 DOM 구조를 위해 항상 렌더링하고, 표시할 읽기·입력 UI가 없을 때 `room-interface--empty` 클래스로 레이아웃에서 숨긴다.

카메라, 사진 검토, 폴라로이드 생성, 믹스테이프 오버레이는 기존처럼 `room-stage` 전체 오버레이로 유지한다.

## 상태별 배치

### Idle

- `room-visual`이 전체 폭을 사용한다.
- 도치와 컨트롤러는 중앙에 유지한다.
- 작은 Idle 안내만 표시한다.
- 빈 인터페이스 공간은 만들지 않는다.

### 대화와 입력 선택

- 도치와 컨트롤러는 시각 영역에 유지한다.
- 대사와 선택 버튼은 인터페이스 영역에 세로로 배치한다.
- 대사 아래에 선택지가 자연스럽게 이어진다.

### 업로드와 텍스트 입력

- 입력 패널은 인터페이스 영역의 전체 폭을 사용한다.
- 업로드 박스 내부에는 패턴, 낙서, 그라데이션을 사용하지 않는다.
- 이미지 미리보기, 삭제, 수정, 건네기 버튼은 동일한 읽기 흐름 안에 배치한다.
- 데스크톱에서 패널 내용이 길면 인터페이스 영역만 스크롤한다.
- 모바일에서는 패널 내부 중첩 스크롤을 줄이고 페이지 흐름으로 확장한다.

### OCR 검수와 오류

- 제목, 설명, 경고, 곡 행, 수정 필드, 액션 버튼 순서로 읽힌다.
- 곡 행은 불투명한 배경과 명확한 구분선을 사용한다.
- 재시도와 대체 입력 버튼은 캐릭터나 컨트롤러 위에 놓이지 않는다.

### LP와 Recording

- LP, 도치, 컨트롤러는 시각 영역 안에서만 움직인다.
- 안내 대사와 진행 상태는 인터페이스 영역에 표시한다.
- 에너지와 조명 효과는 UI 대비를 침범하지 않는다.

### 카메라와 최종 믹스테이프

- 기존 전체 오버레이 구조와 기능을 유지한다.
- 오버레이 카드에는 불투명한 종이 배경을 사용한다.
- 카메라 설명, 촬영 버튼, 결과 제목, 취향 분석, 곡 목록, 플랫폼 버튼은 모두 UI 고딕체를 사용한다.

## 타이포그래피

### UI 폰트

자체 번들되는 Pretendard를 기본으로 사용한다.

```css
--font-ui: "Pretendard", -apple-system, BlinkMacSystemFont, "Segoe UI",
  "Apple SD Gothic Neo", sans-serif;
```

Pretendard 로딩 실패 시 시스템 고딕체로 대체한다.

적용 범위:

- 도치 대사
- 제목과 설명문
- 버튼과 입력값
- 오류와 상태 메시지
- OCR 검수 목록
- LP 안내와 에너지 상태
- 카메라 UI
- 결과 화면과 음악 플랫폼 UI
- 상단 상태처럼 사용자가 읽어야 하는 모든 정보

### 장식 폰트

Gaegu는 다음 요소에만 사용한다.

- 배경 메모
- 낙서 라벨
- 장식용 짧은 문장
- 의미 전달의 주체가 아닌 손그림 표기

브랜드명이나 상단 상태가 실제 내비게이션·상태 정보 역할을 할 때는 UI 고딕체를 사용한다.

### 크기와 행간

- 도치 대사: 20~24px, 600~700, 행간 1.55
- 화면 제목: 22~28px, 700, 행간 1.3
- 본문과 설명: 최소 15~16px, 행간 1.6
- 버튼: 15~16px, 700, 최소 높이 44px
- 라벨과 보조 정보: 최소 12~13px, 행간 1.45

모바일에서도 본문은 15px 아래로 축소하지 않는다.

## 시각 우선순위

1. 제목과 도치 대사
2. 현재 해야 할 행동과 기본 버튼
3. 설명과 입력 내용
4. 캐릭터와 DJ 장면
5. 배경 낙서와 장식

인터페이스 영역의 배경은 `--sketch-paper-bright`와 같은 불투명한 종이색을 사용한다. 버튼과 입력창 뒤에는 장면, 이미지, 그라데이션, 낙서를 두지 않는다.

## 배경 낙서와 손그림 표현

- 낙서는 시각 영역 안에서만 표시한다.
- 기본 opacity는 `0.10~0.16`으로 제한한다.
- 텍스트와 버튼의 뒤에는 낙서를 배치하지 않는다.
- 손그림 테두리의 미세한 비대칭은 유지한다.
- 인터랙티브 요소의 회전은 최대 약 `0.1deg`로 제한해 글자 기울기를 최소화한다.
- 업로드 박스 내부는 단색 배경과 한 줄 테두리만 사용한다.
- 장식 요소는 `pointer-events: none`을 유지한다.

## 대비와 접근성

- 기본 글자색은 `--sketch-ink`를 사용한다.
- 보조 글자색은 현재보다 진한 회색으로 조정한다.
- 비활성 버튼도 배경과 구분되는 테두리를 유지한다.
- 포커스 링은 최소 2px과 충분한 offset을 유지한다.
- 버튼의 터치 영역은 최소 44px 높이를 보장한다.
- `prefers-reduced-motion` 규칙을 유지한다.
- 가로 스크롤이 생기지 않아야 한다.

## 반응형 기준

### 1440px

- 58/42 2열
- 인터페이스 영역 최대 읽기 폭을 제한
- 장면과 UI 사이에 충분한 여백과 손그림 구분선 제공

### 1024px

- 54/46 2열
- 캐릭터와 컨트롤러 크기를 줄여 시각 영역 안에 유지
- UI 본문 크기는 축소하지 않음

### 768px

- 상단 시각 영역, 하단 인터페이스의 1열
- 선택 버튼과 입력 액션을 폭에 맞게 재배치
- 장면과 UI 사이에 명확한 간격 제공

### 모바일 390px

- 시각 영역 높이를 제한
- 캐릭터와 컨트롤러를 시각 영역 안에서 축소
- 인터페이스는 전체 폭의 문서 흐름
- 버튼을 세로로 쌓고 44px 높이 유지
- 긴 파일명과 곡 정보는 줄바꿈

## 테스트와 검증

### 자동 테스트

- `DochiRoom`에 `room-visual`과 `room-interface`가 존재하는지 확인
- `room-interface`는 안정적인 DOM 구조를 위해 항상 유지하되, Idle에서 `room-interface--empty`로 숨겨지는지 확인
- 대화·입력·검수 요소가 인터페이스 래퍼 안에 렌더링되는지 확인
- 테마에서 `--font-ui`와 `--font-note`의 역할이 분리되는지 확인
- 대사, 버튼, 패널, 결과 텍스트가 UI 폰트를 사용하는지 확인
- 업로드 영역에서 장식 배경이 제거되는지 확인
- 배경 낙서 opacity와 시각 영역 제한 규칙 확인
- 기존 기능 테스트 전체 실행
- TypeScript와 프로덕션 빌드 실행

### 시각 검증

1440px, 1024px, 768px, 390px에서 다음 상태를 확인한다.

- Idle
- 대화와 선택 메뉴
- 업로드 또는 텍스트 입력
- OCR 추출 상태와 검수
- 오류 패널
- LP 인터랙션과 Recording
- 카메라·사진 검토
- 최종 믹스테이프

각 화면에서 다음을 점검한다.

- 도치 또는 컨트롤러가 UI를 가리지 않음
- 버튼 뒤에 장식이나 이미지가 없음
- 제목, 설명, 버튼이 먼저 읽힘
- 텍스트 대비와 행간이 충분함
- 패널 잘림과 가로 스크롤이 없음
- 44px 미만의 주요 버튼이 없음
