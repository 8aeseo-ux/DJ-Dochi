# DJ DOCHI 단일 작업실 UI 복원 및 가독성 개선 설계

## 배경

최근 가독성 개선 작업에서 데스크톱 화면을 왼쪽 캐릭터 무대와 오른쪽 UI 패널로 분리하고, 모바일에서는 두 영역을 세로로 쌓는 구조를 도입했다. 이 구조는 캐릭터와 UI의 겹침을 줄였지만, 사용자가 하나의 DJ 작업실 안에서 도치와 대화한다는 기존 경험을 약화했다.

이번 변경은 2열 레이아웃을 제거하고 이전의 단일 작업실 장면을 복원한다. 기능과 상태 흐름은 유지하면서, 대화창만 불투명한 종이 배경으로 바꾸고 모든 기능성 텍스트를 깔끔한 고딕체로 통일한다.

## 목표

- 모든 상태를 하나의 고정된 DJ 작업실 장면 안에서 보여준다.
- 최근 도입한 데스크톱 2열 구조와 모바일 세로 스택 구조를 제거한다.
- 도치, DJ 컨트롤러, 대화창, 입력 패널, LP, 결과 오버레이의 기존 공간 관계를 복원한다.
- 대화창에 불투명한 밝은 종이 배경을 적용해 캐릭터와 배경 위에서도 대사가 선명하게 읽히게 한다.
- 대사, 버튼, 설명, 입력, OCR 검수, 분석 상태, 결과 등 모든 기능성 텍스트를 Pretendard 기반 고딕체로 통일한다.
- 손글씨 폰트는 배경 낙서, 장식 메모, 사인처럼 읽기 흐름에 영향을 주지 않는 장식 요소에만 사용한다.
- OCR, 취향 분석, LP 인터랙션, 카메라 촬영, 믹스테이프 결과 흐름을 변경하지 않는다.

## 비목표

- 상태 머신, API 요청, 데이터 타입, 추천 파이프라인을 변경하지 않는다.
- 캐릭터 이미지나 DJ 컨트롤러 에셋을 교체하지 않는다.
- 새로운 기능, 화면, 페이지 이동을 추가하지 않는다.
- 모든 패널을 불투명 카드로 바꾸지 않는다. 이번 변경에서 명시적으로 불투명해지는 핵심 요소는 대화창이다.
- 이전 커밋으로 브랜치 전체를 되돌리지 않는다. 필요한 JSX와 테마 스타일만 선택적으로 복원한다.

## 레이아웃 구조

`DochiRoom`은 다시 단일 `.room-stage`를 루트 장면으로 사용한다.

최근 추가된 다음 레이아웃 전용 구조는 제거한다.

- `.room-stage--with-interface`
- `.room-visual`
- `.room-interface`
- 화면 너비에 따라 두 영역을 나누거나 세로로 재배치하는 Grid/Flex 규칙

도치와 DJ 컨트롤러는 이전처럼 작업실 중심 무대에 유지한다. 대화창, 선택지, 오류 메시지와 입력 패널은 상태에 따라 같은 장면 안에서 나타난다. 컴포넌트 렌더링 조건과 이벤트 핸들러는 그대로 두고, 레이아웃을 위한 래퍼만 제거한다.

## 대화창 표현

`DialogueBox`의 외곽은 기존 손그림 스타일을 유지하되 다음 가독성 규칙을 적용한다.

- 배경은 완전히 불투명한 밝은 종이색을 사용한다.
- 텍스트와 배경의 명도 대비를 충분히 확보한다.
- 대화창 내부 여백을 유지해 긴 한국어 문장도 답답하지 않게 읽히도록 한다.
- 손그림 테두리와 아주 미세한 비정형 회전은 유지하되 텍스트 자체는 기울이지 않는다.
- 배경 낙서나 캐릭터 이미지가 대화창 내부로 비치지 않게 한다.

입력 패널, OCR 검수창, 결과 오버레이는 이전 단일 장면 스타일을 복원하되 기존 컴포넌트별 배경 정책을 유지한다.

## 타이포그래피 역할

두 가지 폰트 역할을 명확히 분리한다.

### 기능성 UI 텍스트

Pretendard를 사용하는 `--font-ui` 토큰을 적용한다.

- 도치의 모든 대사
- 버튼과 선택지
- 제목과 설명문
- 입력 필드와 플레이스홀더
- 업로드 안내와 개인정보 안내
- OCR 추출 및 검수 텍스트
- 분석 및 오류 상태
- LP 인터랙션 안내와 상태
- 카메라 촬영 UI
- 믹스테이프 제목, 곡 목록, 추천 이유, 플랫폼 버튼

### 장식 텍스트

손글씨 폰트인 `--font-note`는 다음처럼 장식 목적의 짧은 요소에만 사용한다.

- 배경 낙서
- 작업실 주변의 짧은 메모
- 장식 라벨
- 도치의 사인
- 의미 전달에 필수적이지 않은 장식성 텍스트

기본 `body`, 버튼, 입력 요소는 `--font-ui`를 상속하도록 설정하고, 손글씨가 필요한 장식 선택자만 명시적으로 `--font-note`를 사용한다.

## 반응형 동작

1440px, 1024px, 768px, 390px 모두에서 단일 작업실 구도를 유지한다.

- 화면 폭에 따라 2열 또는 세로 스택으로 전환하지 않는다.
- 기존 단일 장면의 크기 조절과 오버레이 위치 규칙을 복원한다.
- 좁은 화면에서는 캐릭터와 컨트롤러의 크기를 유동적으로 줄이고, 대화창과 입력 패널은 사용 가능한 너비 안에서 확장한다.
- 모바일에서 버튼과 입력 요소의 터치 영역을 유지한다.
- 화면 밖으로 잘리거나 가로 스크롤이 생기지 않게 한다.

## 구현 범위

주요 수정 대상은 다음과 같다.

- `src/components/DochiRoom.tsx`
  - 2열 레이아웃 전용 래퍼와 조건부 클래스 제거
  - 이전 단일 작업실 렌더링 구조 복원
  - 상태, 이벤트, 데이터 전달 로직 유지
- `src/styles/sketch-theme.css`
  - 2열/세로 스택 레이아웃 규칙 제거
  - 이전 단일 장면 스타일 복원
  - 대화창 불투명 배경 추가
  - 기능성 텍스트와 장식 텍스트의 폰트 역할 분리
- 필요 시 관련 스타일 테스트
  - JSX 구조와 테마 규칙의 회귀 방지

Pretendard 패키지와 현재 폰트 import는 유지한다.

## 데이터와 상태 흐름

변경하지 않는다.

`useDjDochiFlow`가 관리하는 OCR, 취향 분석, LP, 카메라, 결과 상태와 액션은 그대로 유지한다. `DochiRoom`은 현재와 동일한 props와 상태 값을 자식 컴포넌트에 전달한다. 이번 변경은 DOM 레이아웃과 CSS 표현에만 영향을 준다.

## 테스트 전략

작업은 회귀 테스트를 먼저 추가하거나 기존 테스트를 갱신한 뒤 구현한다.

### 구조 테스트

- `DochiRoom`에 `.room-visual`, `.room-interface`, `.room-stage--with-interface`가 남아 있지 않은지 확인한다.
- 주요 상태별 컴포넌트가 기존과 동일하게 렌더링되는지 확인한다.
- OCR, LP, 카메라, 결과로 이어지는 이벤트 핸들러가 유지되는지 확인한다.

### 스타일 테스트

- 대화창에 불투명 종이 배경이 적용되는지 확인한다.
- 기능성 UI 선택자가 `--font-ui`를 사용하는지 확인한다.
- 배경 낙서와 장식 선택자만 `--font-note`를 사용하는지 확인한다.
- 2열 및 세로 스택 전용 규칙이 제거됐는지 확인한다.

### 전체 검증

- 관련 집중 테스트
- 전체 테스트
- TypeScript 검사
- 프로덕션 빌드
- 1440px, 1024px, 768px, 390px 시각 검증
- OCR 입력부터 FinalMixtape까지 핵심 흐름 스모크 테스트

## 예상 결과

사용자는 다시 하나의 DJ 작업실 안에서 도치와 상호작용하게 된다. 이전의 스케치북 감성과 캐릭터 중심 구도는 유지되며, 대화창은 불투명한 종이 배경 덕분에 안정적으로 읽힌다. 기능에 필요한 모든 텍스트는 고딕체로 통일되어 읽기 쉬워지고, 손글씨는 장식으로만 남아 스케치북 분위기를 보조한다.
